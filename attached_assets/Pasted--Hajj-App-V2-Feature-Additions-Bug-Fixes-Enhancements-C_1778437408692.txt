### B1. Hajj Types Explanation (research and implement correctly)

There are 3 valid types of Hajj. The user selects one during onboarding or from settings:

  IFRAD (الإفراد):
    - Pilgrim performs Hajj only, no Umrah combined
    - Does NOT slaughter (no hady required)
    - Ihram is for Hajj only from the very start
    - Manasik sequence: Ihram → Tawaf Qudum → Stay in Mina (8th) →
      Wuquf Arafat → Muzdalifa → Rami → (no Nahr required) → Halq/Taqsir →
      Tawaf Ifada + Sa'i (if not done) → Mina days → Tawaf Wada'
    - Note: Maliki madhab — Tawaf Qudum is Sunnah not Wajib for Ifrad

  TAMATTU' (التمتع):
    - Performs Umrah first in Hajj months, then releases Ihram, then re-enters Ihram for Hajj
    - Hady (slaughter) is REQUIRED (Rukn according to majority)
    - Most common for non-residents of Mecca
    - Sequence: Umrah Ihram → Tawaf + Sa'i → Halq/Taqsir → EXIT IHRAM →
      Re-enter Ihram on 8th → Mina → Arafat → Muzdalifa → Rami → Nahr (required) →
      Halq → Tawaf Ifada → Mina days → Tawaf Wada'

  QIRAN (القران):
    - Combines Hajj and Umrah in ONE Ihram, never exits Ihram until Mina
    - Hady is REQUIRED (same as Tamattu')
    - One Tawaf and one Sa'i suffices for both (Maliki: recommended to do two)
    - Sequence: Combined Ihram → Tawaf Qudum + Sa'i → Stay in Ihram →
      Mina → Arafat → Muzdalifa → Rami → Nahr → Halq → Tawaf Ifada → Mina → Wada'

### BUG 2: Navigation Screen Returns Wrong Results

Root cause analysis and complete fix:

  Issue 1 — Bearing calculation wrong:
    The bearing formula must use atan2(y, x) NOT atan2(x, y).
    Correct implementation:
      double calculateBearing(double lat1, double lon1, double lat2, double lon2) {
        final lat1Rad = lat1 * pi / 180;
        final lat2Rad = lat2 * pi / 180;
        final dLon = (lon2 - lon1) * pi / 180;
        final y = sin(dLon) * cos(lat2Rad);
        final x = cos(lat1Rad) * sin(lat2Rad) -
                  sin(lat1Rad) * cos(lat2Rad) * cos(dLon);
        final bearing = atan2(y, x) * 180 / pi;
        return (bearing + 360) % 360; // normalize to 0-360
      }
    Add unit tests for known coordinate pairs:
      - Mina → Kaaba: should be ~270° (west)
      - Kaaba → Arafat: should be ~120° (southeast)

  Issue 2 — Arrow not accounting for device rotation:
    The arrow should point NORTH-relative to destination, MINUS device heading.
    arrowRotation = bearingToDestination - deviceHeading
    If deviceHeading unavailable → show bearing degrees as text only, no rotating arrow

  Issue 3 — Distance sometimes shows 0 or NaN:
    - Guard against null GPS before calculating
    - Guard against identical coordinates (distance = 0 is valid — show "أنت هنا")
    - Add null safety throughout NavigationService

  Issue 4 — ETA unrealistic:
    - Hajj walking speed is ~0.8 m/s (slower due to crowds, elderly)
    - Add crowd factor: if zone = mina during rami days → use 0.5 m/s
    - Show range: "~10 - 15 دقيقة" not exact

### ENHANCEMENT 4: Navigation — Real Bird's-Eye Compass Arrow

  Complete rewrite of compass_navigation_screen.dart:

  The arrow must behave like a GPS compass (bird navigation) — it always points
  toward the destination relative to which way the DEVICE IS FACING.

  Correct implementation:

    Step 1 — Get device heading (magnetic north):
      // Use flutter_compass package
      FlutterCompass.events!.listen((CompassEvent event) {
        deviceHeading = event.heading ?? 0; // degrees from magnetic north
      });

    Step 2 — Calculate bearing to destination:
      double bearingToDestination = calculateBearing(
        currentLat, currentLng, destLat, destLng
      );

    Step 3 — Calculate arrow rotation:
      // Relative angle = where destination is, relative to device facing direction
      double arrowAngle = bearingToDestination - deviceHeading;
      // Normalize to -180 to 180 for shortest rotation
      arrowAngle = ((arrowAngle + 540) % 360) - 180;

    Step 4 — Animate smoothly:
      // Use AnimationController to smoothly interpolate between angle values
      // Avoid jumping from 359° to 0° — always take shortest path
      _animController.animateTo(
        arrowAngle / 360,
        duration: Duration(milliseconds: 200),
        curve: Curves.easeOut,
      );

  Compass UI (CustomPainter):
    - Outer ring: compass rose with N/S/E/W Arabic labels (ش/ج/ش.ق/غ)
    - Cardinal dots at 45° intervals
    - Center: large directional arrow (animated, smooth rotation)
    - Arrow style: thick, solid, with arrowhead — not thin line
    - Arrow color: green when distance < 200m, amber 200-500m, white/blue otherwise

  Fallback (if no compass sensor or permission denied):
    - Use GPS track direction (bearing between last 2 GPS points)
    - Minimum speed for track direction: 0.5 m/s (don't use if standing still)
    - Show message: "حرّك جهازك للحصول على اتجاه أدق"
    - Display static arrow with bearing text: "اتجه شمالاً — 847 م"
